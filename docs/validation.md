# 검증 범위

무엇을 어떤 컴퓨터에서 실제로 확인했는지, 무엇은 확인하지 않았는지 적어 둡니다. "자동 검사 통과", "스틸·검수 시트 확인", "실제 재생 확인"은 서로 다른 주장입니다.

## 2026-11-09 · MacBook Pro (Apple M2 Max, macOS 26.4)

환경: Python 3.13.7, numpy 2.5.4, opencv-python-headless 5.0.0.93, scipy 1.18.1, pycolmap 4.2.1, moderngl 5.12.0, Pillow 12.3.0, FFmpeg 7.1.1, Node 24.14.1, three 0.180.0. OpenGL 컨텍스트는 `4.1 Metal - 90.5 / Apple M2 Max`였습니다. 작업 폴더는 외장 SSD를 썼습니다.

이 패키지의 새 `.venv`에서 세 숏을 **소스 다운로드부터** 다시 만들었습니다. Pexels와 Poly Haven에서 받은 파일은 모두 기록된 SHA-256과 일치했습니다.

수치는 1280×720 기준입니다. 원본(2026-11-06 Codex 세션)은 COLMAP 3.12 CLI로 특징을 추출하고 매칭했고, 이 패키지는 pycolmap 4.2.1로 같은 설정을 씁니다. 그래서 오차가 0.07px 안팎으로 다릅니다. 물체 크기(`water_scale`)는 원본과 0.1% 이내로 같았습니다.

**pycolmap으로 바꾸면서 생긴 문제와 수정**: 처음에는 특징 추출 단계부터 초점 850px를 사전값으로 넣었습니다. 그러면 2시점 검증이 보정된 E 행렬로 바뀌는데, 채석장 숏에서 p95가 3.49px까지 나빠져 검수에 실패했습니다. 원본과 같은 순서로 고쳤습니다. 매칭은 초점 사전값 없이(미보정 F/H) 하고, 매핑 직전에만 고정 초점을 넣습니다. 그 뒤 위 표처럼 세 숏이 모두 통과했습니다. 실패한 첫 시도의 기록은 테스트 작업 폴더에 따로 보존했습니다.

**새 클론에서 처음부터**: 커밋된 파일만 새 폴더에 클론했습니다. 그다음 `setup_environment.py --install`로 `.venv`와 three.js를 새로 설치하고 `--check`가 `"ready": true`인 것을 확인한 뒤 `composite hall_water`를 실행했습니다. 결과는 통과입니다(p95 1.352px, 최대 4.496px, 검증 트랙 756개, 영상 96/96).

같은 입력이어도 실행마다 수치가 조금 다릅니다. 실내 물의 p95는 1.469px와 1.352px가 나왔습니다. pycolmap의 특징 추출·매칭·매핑이 멀티스레드로 돌기 때문입니다. 비교는 정확한 값이 아니라 위 통과 기준으로 합니다.

### 원본과 비교한 결과

- 실내 물 48번 프레임: 원본 렌더와 평균 픽셀 차이 0.25/255.
- 채석장 재조명 48번 프레임: 원본 v2와 평균 픽셀 차이 0.04/255.

### 사람이 확인한 범위

세 숏의 시작·중간·끝 프레임과 정원 숏의 검수 시트 한 장(48~71번)을 직접 봤습니다. 카메라 점프, 바닥 미끄러짐, 검은 프레임은 보이지 않았습니다. **이번 패키지 재현에서 각 MP4를 처음부터 끝까지 실시간으로 재생해 보지는 않았습니다.** 같은 공정으로 만든 원본 결과는 2026-11-06에 QuickTime으로 전체 재생 검수를 했습니다.

### 재료 찾기 도구 (`scripts/find_materials.py`)

- `hdri`: Poly Haven 공개 API로 실제 검색했습니다(`forest overcast`, `--category indoor`).
- `footage`: API 키가 없는 상태에서 검색 페이지 주소를 출력하는 것만 확인했습니다. **Pexels·Pixabay API 응답은 문서에 나온 형식의 예시 데이터로 단위 테스트만 했고, 실제 키로 검색해 보지는 않았습니다.**
- `sheet`: 실내 물 원본의 0~4초로 12프레임 시트를 만들어 기둥 사이의 시차가 보이는 것을 확인했습니다.
- `new-shot`: 실내 물 영상과 다른 HDRI(`hochsal_forest`)로 임시 숏을 만들었습니다. 해시, 길이·크기, 구간 시트, `shots/*.json`이 올바르게 나왔습니다. 이어서 `fetch`가 두 파일의 해시를 대조해 통과하는 것까지 확인한 뒤 임시 숏은 지웠습니다. 같은 이름으로 다시 만들면 덮어쓰지 않고 멈춥니다.

## 확인하지 않은 것

- **Windows·Linux에서 실제로 처음부터 끝까지 실행해 보지 않았습니다.** 확인한 것은 다음과 같습니다. pycolmap 4.2.1과 moderngl 5.12.0의 Windows x64 휠이 있습니다. 코드는 심볼릭 링크와 POSIX 전용 기능(`fcntl` 등)을 쓰지 않습니다. GitHub CI(`.github/workflows/test.yml`)가 macOS·Windows·Ubuntu에서 단위 테스트, 컴파일, SPH 굽기, 물 표면 생성을 검사합니다. GitHub 러너에는 GPU가 없어서 OpenGL 렌더 자체는 CI에서 검사하지 않습니다.
- **SPH 굽기는 CPU 종류마다 결과가 다릅니다.** 2026-11-09 첫 CI에서 Windows와 Ubuntu(x64)는 서로 같은 해시(`3a5e2101…`)가 나왔고, Mac(arm64)의 해시(`5048a921…`)와는 달랐습니다. 처음에는 "모든 OS에서 같은 해시"를 검사하도록 잘못 작성했다가, CPU 종류별로 기록한 해시와 비교하도록 고쳤습니다(`tests/check_sph_bake.py`). 그래서 Windows PC에서 만든 물의 움직임은 Mac 결과와 조금 다를 수 있습니다. 그 차이가 화면에서 얼마나 보이는지는 확인하지 않았습니다.
- 렌즈 캘리브레이션, 실측 스케일, 촬영 현장의 조명은 측정하지 않았습니다. 모두 가정값입니다([README](../README.md#꼭-알아야-할-가정)).
- Drift 예제는 원래 저장소 그대로 옮겼고, 이번에 다시 실행하지 않았습니다. 검증 범위는 [Drift 문서](drift.md)에 있습니다.
- 백보드 물(PnP)은 이 패키지에서 절차 생성 데모 12프레임(960×540)만 Mac에서 다시 실행했습니다. 세 영상이 모두 12프레임이었고, 네 모서리 PnP 피팅 p95는 3×10⁻⁶px입니다. 이 값은 같은 네 점에 대한 피팅이라 독립 검증이 아닙니다. 실사 플레이트와 실제 모서리 추적이 들어간 원작업(Windows)은 이 패키지에 없습니다.
