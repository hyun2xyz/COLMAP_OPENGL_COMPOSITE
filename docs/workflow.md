# 워크플로

명령은 모두 저장소 폴더에서 `python -m pipeline <단계> <숏>`으로 실행합니다(`python`은 프로젝트 `.venv`의 Python). 각 단계는 앞 단계가 `work/<숏>/`에 남긴 파일을 읽습니다. `python -m pipeline status <숏>`을 실행하면 어디까지 끝났는지와 다음 명령이 나옵니다. 아래 시간은 Apple M2 Max에서 4초(96프레임) 숏 하나를 처리한 실측값입니다.

## 1. fetch — 소스 받기 (첫 회 수십 초)

`shots/<숏>.json`의 `source.download`와 `hdri.download`에서 파일을 받아 SHA-256을 대조합니다. 해시가 다르면 배포처가 파일을 바꾼 것입니다. 이때는 멈추고 라이선스와 파일을 다시 확인합니다. 라이선스 기록은 `source/license.json`에 남습니다. Pexels License는 수정과 사용을 허용하지만 CC0는 아닙니다. 원본을 수정하지 않은 채 다시 배포하는 것은 금지되므로, 원본 영상은 저장소에 넣지 않습니다.

## 2. prepare — 작업 플레이트 (5초)

`plate.start`부터 `plate.duration`초를 자르고, `plate.fps`의 일정한 프레임레이트와 `plate.size` 크기로 바꿉니다. 모든 단계는 `frames/frame_000000.png`를 0번 프레임으로 셉니다. 키프레임은 `keyframe_stride` 간격에 마지막 프레임을 더해 **복사**합니다. Windows에서 링크 권한 문제가 없도록 복사 방식을 씁니다.

## 3. solve — 카메라 (20~30초)

1. 키프레임에서 SIFT 특징을 CPU로 추출하고 순차 매칭합니다(overlap 8). 이때 **초점 사전값을 넣지 않습니다.** 잘못된 초점으로 보정된(E 행렬) 검증을 하면 매칭 분류가 틀어집니다. 채석장 숏에서 실제로 p95 3.5px까지 나빠졌습니다.
2. 매칭이 끝난 뒤에 카메라를 `SIMPLE_PINHOLE`(`focal_px`, 화면 중심)로 고정하고 증분 복원합니다. 키프레임이 **전부** 등록되지 않으면 멈춥니다.
3. 3D 점 ID가 5의 배수인 랜드마크(20%)를 삭제하고 관측 기록만 남긴 뒤 번들 조정을 다시 합니다. 이렇게 지운 점은 카메라 계산에 쓰이지 않고 검수에만 쓰입니다.
4. `tracking/measure.py native`가 키프레임 사이의 모든 프레임에 대해 양쪽 키프레임에서 양방향 LK로 점을 따라가고, RANSAC PnP(EPnP) + LM으로 포즈를 계산합니다. 보간으로 메운 프레임은 없습니다.
5. `tracking/export_colmap.py`로 `Camera_Three.json`(Three/OpenGL 축, column-major `matrixWorld`)을 씁니다.

## 4. qa-camera — 통과해야 다음으로 (3초)

지운 랜드마크를 첫·끝 관측으로 삼각측량하고, 그 사이 프레임에 재투영해 오차를 잽니다. 2~6프레임 간격은 양방향 LK 관측도 더합니다. 큰 오차도 빼지 않고 그대로 셉니다.

| 항목 | 기준 | 실내 물 | 정원 공 | 채석장 천 |
| --- | --- | ---: | ---: | ---: |
| 검증 트랙 | ≥ 40 | 735 | 897 | 1,087 |
| p95 | < 2px | 1.469 | 1.418 | 1.397 |
| 최대 | < 8px | 4.710 | 5.085 | 4.222 |
| 프레임 간 이동 p95 | < 1px | 0.270 | 0.244 | 0.191 |

새 패키지로 다시 계산한 값입니다. 정확한 수치와 날짜는 [검증 범위](validation.md)에 있습니다. 통과하지 못하면 이 카메라로 합성하지 않습니다. `focal_px`를 바꿔 보거나(예: 750 / 850 / 1000을 각각 새 `--work`에서 풀어 비교), 구간을 줄이거나, 다른 영상을 고릅니다. 한 번에 한 가지만 바꿉니다.

## 5. ground — 바닥 맞추기 (1초)

중간 프레임에서 바닥 영역에 있는 3D 점들로 평면을 찾습니다. 영역은 기본 화면 아래쪽 / `topdown`이면 가운데 / `roi`를 주면 그 사각형입니다. 그다음 평면 법선을 Y축으로 두고, `anchor` 픽셀에서 쏜 광선이 평면에 닿는 곳을 원점으로 삼습니다. 스케일은 중간 카메라 높이가 1.6이 되도록 맞춥니다. 물체 크기는 `width_fraction`(화면 폭 대비 비율)으로 정합니다.

**반드시 `qa/ground-fit.jpg`를 엽니다.** 초록 점이 실제 바닥 위에 있고, 빨간 십자가 물체를 세울 자리에 있어야 합니다. 벽이나 수풀에 점이 몰려 있으면 `roi`를 좁힙니다. 칠한 바닥처럼 무늬가 적으면 기본 영역에 점이 모자라 멈춥니다. 그때 생기는 `qa/ground-candidates.jpg`에서 바닥 위의 초록 점(선·화살표·주차선 등)을 감싸도록 `roi`를 정합니다. 기둥이나 나무가 물체 앞을 지나가는 자리는 피하세요. 이 패키지는 가림 마스크를 만들지 않습니다.

## 6. simulate · render · qa-video (약 20초)

- `water`: `Water/bake-water.mjs`(SPH 370입자)를 한 번 굽고, 프레임마다 MarchingCubes 표면을 만듭니다. 굽기 결과는 같은 종류의 CPU에서는 항상 같습니다. 다만 Apple Silicon(arm64)과 일반 PC(x64)는 부동소수점 계산이 조금 달라서 해시가 다르고, 시뮬레이션이 진행될수록 입자 위치 차이가 커질 수 있습니다. CI가 CPU 종류별로 기록한 해시와 비교합니다(`tests/check_sph_bake.py`).
- `rigid_spheres`: 구 7개, 낮은 중력, 바닥·원형 벽·충돌 반발. `cloth`: 네 모서리를 기둥에 고정한 33×25 PBD 천에 중력과 바람.
- `render`: 프레임마다 카메라로 view와 projection을 만들고, 플레이트를 텍스처로 올리고, 깊이 테스트로 CG를 그립니다. 1.5배 SSAA를 premultiplied 상태로 축소합니다. `Alpha.mov`는 straight 알파입니다. 물의 굴절에는 이 플레이트가 들어가 있어서 다른 배경에는 쓸 수 없습니다. `--shadow analytic|ring|none`으로 그림자 방식을 바꿀 수 있습니다.
- `qa-video`: 모든 프레임을 ffmpeg로 디코드합니다(BT.709 반영). 알파 바깥의 배경 MAE가 4/255 미만이고 프레임이 빠지거나 중복되지 않았는지 검사합니다.

**그다음 사람이 확인합니다.** `review_*.jpg` 시트 4장을 보고, `Composite.mp4`를 처음부터 끝까지 재생합니다. 카메라 점프, 바닥에서 미끄러짐, 떨림, 잘못된 가림, 검은 프레임이 없는지 봅니다. 자동 검사 통과만으로는 완료가 아닙니다.

## 7. light · relight — 조명 통합

`render`의 결과는 고정된 빛과 단순한 그림자입니다. 실사에 녹아들게 하려면 이 단계를 더합니다. 결과는 `relight/final/`에 나오고, `python -m pipeline qa-video <숏> --render <작업 폴더>/<숏>/relight/final`로 검사합니다.

### 공 숏: 플레이트에서 빛을 재고 그 빛으로 다시 그리기 (light 3초 + relight 약 25초)

`python -m pipeline light <숏>`이 **이 장면에서 빛이 어디서 오는지** 잽니다.

1. 키프레임 세 장마다 한 장씩, 화면의 모든 점을 복원한 카메라로 3D 광선으로 바꿉니다.
2. 물체의 지평선 위에서 가장 밝은 3%(천장 조명, 창, 트인 면)를 고릅니다. 각 점은 근처 COLMAP 점의 거리를 빌려 3D에 놓고, **물체 자리에서 본** 방향과 크기로 바꿉니다. 카메라에서 본 방향은 물체에서 본 방향과 다르기 때문입니다.
3. 밝은 곳을 방향에 따라 두 무리로 나눕니다. 무리마다 방향·색·세기·크기를 구합니다(주광과 보조광).
4. 나머지 위쪽 방향의 평균 밝기는 주변광이고, 물체 둘레 실제 바닥의 색과 밝기는 바닥 반사광입니다. 바닥의 평평한 부분에서 그레인 세기도 잽니다.
5. HDRI의 가장 밝은 쪽이 주광과 같은 방향이 되도록 HDRI를 돌리고, 주변광 밝기에 맞춰 HDRI 밝기를 조정합니다.

**반드시 `qa/light-estimate.jpg`를 엽니다.** 노란 화살표(주광)와 파란 화살표(보조광)가 실제 조명·창 쪽을 가리켜야 합니다. `qa/light-probe.jpg`에서는 돌린 HDRI의 밝은 곳이 노란 십자 근처에 있어야 합니다. 카메라가 거의 바닥만 보는 숏(내려다보는 드론 등)은 빛을 잴 수 없어서 멈춥니다. 그런 숏은 `render` 결과를 씁니다.

그다음 `python -m pipeline relight <숏>`이 네이티브 OpenGL로 다시 그립니다.

- 공과 링: 측정한 빛의 확산광과 GGX 하이라이트, 돌린 HDRI 반사가 들어갑니다. 지평선 아래 방향은 HDRI 대신 실제 바닥색을 비추므로, 초록 바닥이면 공 아랫면에 초록 반사광이 생깁니다.
- 그림자: 빛마다 2048 그림자 맵을 만들고, 가리는 물체에서 멀수록 가장자리가 부드러워집니다(빛의 측정 크기 사용). 바닥에는 공과 링의 접촉 그림자(앰비언트 오클루전)를 더합니다. 그림자 농도는 바닥이 받는 빛 가운데 그 빛이 차지하는 비율로 정합니다.
- 질감: 공마다 은은한 얼룩·거칠기·미세 요철을 넣습니다. 공의 움직임에 맞춰 회전시키므로 무늬가 미끄러지지 않습니다.
- 마무리: 플레이트에서 잰 그레인을 CG에만 넣고, 0.5px 블러를 줍니다. 합성은 AE와 같은 방식(Straight RGB + 알파를 플레이트 위에)으로 하며, 그림자는 검은색 + 알파(섀도 캐처)로 `Alpha.mov`에 함께 들어갑니다.

| 설정(`relight`) | 뜻 | 성격 |
| --- | --- | --- |
| `clipped_gain` (기본 8) | 하얗게 날아간 조명 픽셀의 실제 밝기 배수. 클수록 그림자가 진해짐 | 가정값 |
| `max_light_radius_deg` (기본 12) | 빛 크기의 상한. 작을수록 그림자 가장자리가 또렷해짐 | 연출값 |
| `ao_strength` (기본 1) | 접촉 그림자 세기 | 연출값 |
| `exposure`, `blur_sigma`, `grain_scale`, `seed` | 전체 밝기, 가장자리 블러, 그레인 배율, 그레인 시드 | 연출값 |

### 천 숏: 눈으로 추정한 해 (약 1분)

`relight.sun`(월드 기준 해 방향)은 플레이트의 그림자 방향을 보고 **눈으로 추정**한 값입니다. 설정은 다음과 같습니다.

- 따뜻한 직사광, 차가운 하늘광, 약한 지면 반사광. 모두 선형 공간에서 계산합니다.
- UV에 고정된 직조 질감. 천이 움직여도 무늬가 미끄러지지 않습니다.
- 실제 천과 기둥 형상으로 만든 2048 그림자 맵.
- 0.45px premultiplied 블러. 가장자리에 검거나 밝은 테두리가 생기지 않습니다.
- CG 영역에만 시드 고정 그레인.


## 새 영상으로 바꾸기

영상과 HDRI를 고르는 기준과 찾는 순서는 [재료 찾기](materials.md)에 있습니다. 에이전트는 이 문서대로 직접 찾고, 후보를 보여 준 뒤 진행합니다.

1. 수정과 사용을 허용하는 무료 영상을 고릅니다. CC0나 Pexels License가 해당합니다. 무료라고 해서 저작권이 없는 것은 아닙니다. 배포 페이지에서 라이선스를 직접 확인합니다.
2. 하드컷이 없고, 카메라가 **이동**하며(제자리 회전만 하면 깊이가 풀리지 않습니다), 정적인 질감이 보이고, 줌이 고정된 4~5초 구간을 고릅니다.
3. `python scripts/find_materials.py new-shot my_shot --like hall_water --page <페이지> --download <다운로드 URL> --creator <제작자> --license pexels`로 가장 비슷한 예제를 복사해 설정 파일을 만듭니다. 손으로 복사해도 됩니다(`cp shots/hall_water.json shots/my_shot.json`). 그다음 아래 항목을 확인합니다.
   - `source`: 페이지, 제작자, 다운로드 URL. `sha256`은 처음 받은 뒤 `fetch`가 알려 주는 값을 적습니다. 비워 두면 대조하지 않습니다.
   - `plate.start`·`plate.duration`
   - `camera.focal_px`: 모르면 850부터 시작합니다.
   - `ground`: 처음에는 그대로 두고, `ground-fit.jpg`를 본 뒤 고칩니다. 내려다보는 숏을 복사했다면 `topdown`을 지웁니다. 카메라가 앞으로 나아가는 숏은 중간 프레임 기준으로 물체를 놓기 때문에, 기준점(`anchor`)을 화면 위쪽(먼 곳)에 두어야 끝 프레임까지 화면 안에 남습니다.
   - `kind`: `water`, `rigid_spheres`, `cloth` 중 하나.
4. `composite`를 실행하고 4번(카메라)과 5번(바닥)의 검사를 반드시 봅니다.

## 실패했을 때

| 증상 | 먼저 볼 곳 | 고칠 것 |
| --- | --- | --- |
| `Only n/33 keyframes registered` | 영상에 하드컷이나 흐림이 있는지 | 구간을 줄이거나 다른 구간 사용 |
| qa-camera p95가 2px 이상 | `qa/acceptance-camera.json`의 `coverage`, 프레임별 관측 수 | `focal_px` 비교, 움직이는 물체(물·나무·사람)가 많은 구간 피하기 |
| `Only n floor landmarks in the region` | `qa/ground-candidates.jpg` | 바닥 위 초록 점을 감싸도록 `roi` 지정 |
| 물체가 바닥에서 미끄러짐 | `ground-fit.jpg` | `roi`를 실제 평평한 바닥으로 좁히기 |
| 물체가 너무 크거나 작음 | `layout.json`의 `water_scale` | `width_fraction` |
| OpenGL 오류 | `setup_environment.py --check`의 `opengl` | 그래픽 드라이버. Linux 서버라면 `VFX_GL_BACKEND=egl` |
| `... already has files` | — | 결과를 덮어쓰지 않습니다. 새 `--output` 또는 새 `--work` |
